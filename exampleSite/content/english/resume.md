        <p>I've spent nearly 15 years making complicated tech make sense. I've been the founding tech writer at several SaaS, B2B, and open source companies, having built documentation from scratch more than once. I know how to set it up so it doesn't fall apart when the product doubles in size.</p>
        <p>I believe docs should live in Git next to the product and go through review just like the code does. When a team ships constantly, keeping up is the real challenge. I use tools like Claude to work through the steady stream of PRs, specs, and tickets, flag docs that a change has made stale, and get a rough draft started fast. From there, I make sure everything is accurate and useful to the people reading it, and I own every word that ships.</p>
        <p>As a knowledge strategist, I look at the bigger picture. I think about how information is organized, how it connects, where it can be reused, and who keeps it current across help centers, API portals, and internal KBs. I want customers and support teams to find the right answer quickly, and these days that includes the AI assistants reading docs on their behalf.</p>
